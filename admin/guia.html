Guia de publicação

Da ideia
ao seu próximo post.

Um passo a passo para escrever, revisar e publicar no site.

1. Entre no editor

Acesse o estúdio, clique em Abrir editor e entre com sua conta GitHub. O painel usa o login do GitHub, com a autenticação em dois fatores da sua conta. Quando uma senha for necessária, ela será pedida na página do próprio GitHub.

Se aparecer “Acesso aguardando ativação”, a integração de login ainda precisa ser concluída. O painel exibirá a opção de entrada assim que ela estiver pronta.

2. Crie um post

  1. Abra Artigos e histórias e escolha criar um novo post.
  2. Preencha o título, o resumo e o tema. Use Pessoal para experiências, reflexões e aprendizados fora do conteúdo técnico.
  3. Escolha um endereço único, como python-ambientes-virtuais. O artigo ficará em /artigos/python-ambientes-virtuais.html. Depois de publicar, preserve esse endereço.
  4. Escreva o texto. Você pode usar a barra do editor para títulos, listas, links, imagens e código, ou editar diretamente em Markdown.
  5. Se quiser, adicione uma capa, a descrição da imagem, um repositório do GitHub e links de apoio.

A data do post é a data mostrada no artigo. Ela não agenda a publicação: mesmo com uma data futura, o conteúdo pode entrar no ar quando você escolher publicar.

3. Salve e revise

Para publicar um vídeo: abra a coleção Vídeos e escolha Novo Vídeo. Preencha título, descrição, endereço, tema e Link do YouTube. Cole o link normal de compartilhamento, não um código HTML. As notas e materiais são opcionais.

O vídeo continua hospedado no YouTube. Depois de publicar, um player aparece em Vídeos e na página individual, como /videos/python-primeiro-csv.html. Não é necessário criar um artigo. Você pode incluir links para artigos e repositórios nas notas.

Confirme que o vídeo permite incorporação e está disponível para o público desejado. Um vídeo não listado passa a ser encontrável quando seu link é publicado no site; vídeos privados ou com restrições podem não reproduzir. O player só aparece no site publicado, não na prévia padrão do editor.

Salve como rascunho. No fluxo editorial, o post passa pelas etapas Rascunho, Em revisão e Pronto. Você pode fechar o editor e retomar o trabalho depois de salvar.

A prévia do editor ajuda a conferir o conteúdo. Para ver a aparência final, use a prévia do site quando disponível. Revise os links, teste os exemplos e veja se o resumo explica bem o artigo.

Rascunho não significa privado. O site usa um repositório público: textos, imagens e versões salvas podem ser vistos no GitHub, mesmo antes de aparecerem na lista de artigos. Evite senhas, dados de clientes, dados pessoais sensíveis ou material que você ainda precisa manter confidencial.

4. Publique

Quando a revisão estiver concluída, marque o post como pronto e escolha Publicar. Isso integra o texto à versão principal do site. A atualização automática gera o artigo, o índice e o mapa do site; pode levar alguns minutos para a nova versão ficar disponível.

Se houver alguma falha nessa atualização, a versão publicada anteriormente continua disponível. Confira a execução mais recente em Actions no GitHub para saber se a publicação terminou.

Uma estrutura simples para começar

Uma introdução curta: o que vamos resolver?

## O problema
Explique o contexto com um exemplo pequeno.

## Passo a passo
Mostre o código ou as etapas e explique as escolhas.

## O que aprendi
Conte o resultado, uma limitação e o próximo passo.

Nos posts técnicos, use exemplos que o leitor consiga reproduzir. Nos pessoais, troque o passo a passo pela experiência, pelo que mudou e pelo que você quer explorar depois.

Dúvidas comuns

O vídeo não reproduz dentro do site. O que conferir?

Teste o link diretamente no YouTube e confirme a opção “Permitir incorporação” nas configurações do vídeo. Restrições de idade, região, privacidade ou extensões do navegador podem impedir o player. O site mantém um link para assistir no YouTube. Os links devem apontar para um vídeo, não para um canal ou playlist.

Como incluir um código Python ou SQL?

Insira um bloco de código pelo editor ou use três acentos graves no modo Markdown, seguidos de python ou sql. Feche o bloco com mais três acentos graves. Não inclua senhas ou credenciais reais nos exemplos.

Como corrigir um post que já está no ar?

Abra o post na coleção, faça a alteração, salve e percorra o fluxo de revisão e publicação. O endereço continua o mesmo se você mantiver o campo “Endereço do post”.

Por que uma imagem precisa de descrição?

A descrição permite que pessoas que usam leitores de tela compreendam a imagem. Em um gráfico, descreva a conclusão principal; em uma captura de tela, explique a informação relevante.

O editor pode publicar automaticamente toda semana?

O calendário semanal é um lembrete para escrever e publicar. Este painel publica quando você aciona “Publicar”; a data do artigo não funciona como um agendamento.

Como encerrar o acesso?

Use a opção Sair no menu do usuário ao terminar, principalmente em dispositivos compartilhados. Fechar a aba ou o navegador não encerra a sessão do editor. Para revogar a autorização, acesse as aplicações autorizadas nas configurações da sua conta GitHub.
